## 1. Decision rule for the add-on readout (weights vs engine), declared before reading it
Cells: vLLM serving the unquantized training checkpoint (`models/gemma-4-e4b-it`) base and + M0, versus HF bf16 + M0 and vLLM QAT + M0, on the same H-gen / T-fit items and target ids; reference noise = the probe's base-row serving floor (text p95 1.43 nats/token; per-item).
- **Weights branch:** vLLM-unquantized + M0 adapter effect within the floor of HF + M0 (item-wise, text span) AND vLLM-QAT + M0 materially below both (diff-of-diffs beyond the MDE 1.27) → the mismatch is in the base weights (LoRA trained on bf16 unquantized, applied to QAT w4a16) → the fixture (§2) and, if it passes, M0q (§3) are the paper-critical cells.
- **Engine branch:** vLLM-unquantized + M0 ≈ vLLM-QAT + M0 (both materially below HF + M0) → the LoRA application path of the serving engine differs from PEFT → **M0q is NOT run**; the replacement cell is M0 evaluated on vLLM serving the unquantized checkpoint (3 seeds, same matched template and caps) or, if vLLM-unquantized also diverges from HF, HF-generate on a reduced task set; the serving path is the object of the paper's interface section.
- **Mixed / ambiguous** (both arms differ from HF, or differences within the floor): run the fixture anyway; its contrast (§2) decides.

## 2. Fixture (≤ 20 min GPU; runs right after the add-on cells, before A0-capped v052 and v051)
Train a small LoRA (same r16/α16/7 targets, same packer output, same seed and LoRA init) for a fixed number of updates on a fixed subset (the 5 T-fit chunks or a 50-chunk subset, declared in the ledger) against two bases: **(Q)** the dequantized QAT checkpoint (`models/gemma-4-e4b-it-qat-dequant-bf16/` or an in-memory `run_compressed=False` load — the route the design analysis selects; checkpoint hash recorded before scoring) and **(B)** the bf16 unquantized checkpoint. Score the same T-fit target ids teacher-forced under (a) HF loaded with the SAME base the adapter was trained on and (b) vLLM QAT w4a16 + the adapter.
- **Non-degeneracy guard:** each adapter must reach an HF adapter effect ≥ 1.0 nats/token on the text span (otherwise the fixture is void, not passed).
- **Pass for (Q):** |served − HF adapter effect| ≤ the base-row floor (1.43 nats/token text; item-wise) AND served opener accuracy ≥ 0.99 × HF accuracy; AND `depth` and `<|"|>` log-probs within 0.5 nats between stacks.
- **Expected for (B):** the gap persists (served effect materially below HF, as in the probe) — the fixture is a contrast; (Q) pass with (B) gap = weights branch confirmed at the mechanism level; (Q) fail = the dequantization route or the engine path is wrong, M0q is not run until understood.
