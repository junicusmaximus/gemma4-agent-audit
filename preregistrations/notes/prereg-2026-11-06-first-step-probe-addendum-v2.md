## A. Corrections to the original's reasoning
1. **"Packing cannot explain a step-1 failure" — withdrawn.** The orphan-context *conditioning* mechanism is absent at step 1, but gradients computed on history-truncated chunks change the shared LoRA parameters, so packing remains a candidate cause of the step-1 distribution. The probe's value is to find format / weight / serving mismatches cheaply; it neither excludes packing nor decomposes long-horizon behaviour. Steps ≥ 2 (tool response handling, reasoning history, compaction boundary, final submission) are inspected separately.
2. **"Collapse is induced, not copied" — downgraded** to: raw teacher-trajectory frequencies differ from student rollouts. The teacher table was computed on full, success-selected `text_segments`; the student learned history-truncated `chunks`; models, tasks, contexts and denominators differ. Three distributions are reported with separate denominators: raw teacher trajectories, packed supervised targets (chunk view, §C), student rollouts. Not used as a confirmed claim: "not a copy of data statistics", "training alone is the cause", "a cause before packing".
3. **Target completion T** must include the trailing `<|tool_response>` control token (the real first completion ends with it). Control-token spans are scored separately from text spans.

## B. Revised design — paired serializations, same content, same target ids
- **Pairing.** Each probe item is one message content serialized two ways with the SAME target token ids: (i) the training form as `build_sft.py` packs it (QAT tokenizer, stored prefix/completion ids — `sft/build_sft.py:7–14, 26–27, 100–101, 262`), (ii) the served form = the request the harness actually sends, rendered by the served chat template. Target span start/end offsets are recorded in a ledger for both forms; scaffold tokens present in only one form are analysed as a separate span, never folded into the common span.
- **Items.** (T-fit) training-fit items: 3–5 real training trajectories with their stored first completion. (H-gen) held-out items: the 48 holdout first prompts with the modal teacher opener (text + control suffix). Reported in separate tables (fit vs generalization); never pooled.
- **Stacks (2 × 2 per item, same input, same target span).** HF bf16 base / HF bf16 + real M0 adapter / vLLM QAT base / vLLM QAT + the same M0 adapter; M1 afterwards, sequentially (never two large models resident at once). Metrics: per-token NLL and argmax accuracy on the common target span and on the control-token span; top-k at the first action token. **Noise first:** every configuration is scored twice; only changes beyond the repeat-run variability are read.
- **Adapter application evidence** (replaces the "+1 nat" rule): (1) the adapter tensors/layers actually applied in each stack (PEFT module list; vLLM LoRA load log) against `adapter_config.json` (516 tensors, 42 text layers 0–41, r16 / α16, 7 projection targets); (2) the same-input, same-token distribution change base → adapter beyond noise, in either direction — an active adapter may lower the opener's probability, which is not inactivity; (3) a zero-B adapter control through the same path if available; never the difference of two different top tokens' logprobs.
- **Real requests.** The CPU serialization audit's trace-based reconstruction is NOT a stored real request. The GPU step captures the actual request bodies sent to the server (proxy / request logging) for step 1 and for a tool-call → tool-response → next-assistant transition, a compaction boundary and the final submission step, and diffs them against the trained form (tokenizer/model file provenance, assistant prefix, special tokens, stop, tool pairing, reasoning history — on the same input).

## C. Chunk-view teacher statistics (CPU, before the GPU probe)
On the 1,661 M0 training chunks: first supervised action class after the header split by chunk type (first chunk vs later chunk with an orphan start), loop and M5 strata within chunks over supervised transitions, thought presence, supervised-target counts per class, and the share of supervised actions whose preceding call is absent from the chunk (the history-free share). Separate denominators from the raw-trajectory table. Output `analysis/teacher-behaviour-boss-v045/chunk-view/`.

## D. Readings — non-exclusive diagnostics; no causal labels; no "clean"
- **D1 format:** within one stack and one adapter state, NLL / accuracy on the common target span, training form vs served form. Labels: {difference beyond noise on span X / no difference observed within this probe / not measurable}; the differing token spans are listed.
- **D2 adapter application:** {applied and distribution changed beyond noise / applied but no change beyond noise on these spans / not applied (module list) / not measurable}.
- **D3 stack:** between-stack base delta and within-stack adapter deltas on the same spans; the difference of differences is a diagnostic number, never "serving error".
- **D4 training fit:** NLL / accuracy of the stored first completions under HF + adapter vs base at the training-loss positions — descriptive.
- Training, format and serving problems may coexist; "unclassified", "not measurable" and "needs further check" are allowed. A null difference in a small probe is never written as "the interface is sound".
- Branches: (a) a reproducible interface defect → fix that path explicitly, verify it, and re-match the affected comparison arms in a new generation; (b) no defect observed within the limited probe → the H1 data contract is verified on its own (generation permission path, parent ledger, target ancestry/order, +3-token opener, 16k fit, loss denominator, gradient accumulation; "same 208 updates" is never written as "same compute") and the packing experiment is judged on that; (c) insufficient → record which inputs/steps remain unverified; no cause is excluded; CPU audits and independent 31B work continue.
- **H1 is not gated on this probe.** A step-1 result alone neither excludes nor establishes packing. The opener probability is never a proxy for repair success.

## G. Amendment v2.1 — 2026-11-05 15:5x UTC, after the oracle check of this addendum (no run started)

Oracle (read-only) found no structural flaw in the paired 2 × 2 design and set two blocking requirements plus a noise model; Boss adopts them verbatim.
1. **Identical stored token ids to all four cells.** Prompts are fed as token-id sequences (vLLM accepts token-id prompts); text is never re-rendered per stack, because the chat templates differ between the unquantized and the QAT model dirs. The HF + adapter cell loads the exact base the adapter was trained on; the stack axis is labelled **"weights + precision"** (bf16 unquantized vs QAT w4a16), never "precision" alone.
2. **Readout per item** = log-probability and rank of the fixed target span (control-token span and scaffold-only spans separate), paired across cells, direction-agnostic. **Zero-B adapter control is required** (copy the adapter, zero every lora_B tensor; served output must equal the base row within the base-row floor) as the loading-path check.
3. **Noise model.** Repeat runs only verify determinism; vLLM numerics shift with batch composition, so the second scoring uses a different batch layout (or one item per request). Two references: (i) the serving floor = base-row HF-vs-vLLM per-item difference (the honest weights+precision noise); (ii) an item-level paired bootstrap over the 48 held-out prompts for every effect (the training-fit table gets its own bootstrap over its items). "Beyond noise" = the adapter-row cross-stack difference exceeds the base-row floor item-wise (above its 95th percentile) AND the item-bootstrap interval excludes 0.
4. **H1 data-contract checks before any training (six, all must pass):** (1) supervised set identical to M0 — hash of sorted (trajectory, step, token id, label) tuples over labels ≠ −100 equals M0's after excluding the opener-repair tokens, which must number exactly 3 × modified starts and all carry −100; (2) inserted history = the true contiguous prefix of the raw trajectory ids ending at the chunk's first supervised token (no gap, no overlap), checked against the raw ids, not the packer's reconstruction; (3) orphan starts after re-pack = 0, or a listed residual with the overflow rule stated (drop history, never targets); every chunk ≤ 16,384; (4) group manifest hash identical to M0 (208 groups, same chunk-to-group assignment and order), per-group token counts reported (≈ ×1.24 expected); (5) decoded labels ≠ −100 of each M0 chunk and its H1 counterpart are textually identical; (6) inserted history serialized in the served form (template, tool-call form, `<|tool_response>` control tokens) is diffed against a captured real request body from the GPU capture step.
5. **Paper sentence rule.** Only a descriptive three-distribution sentence is defensible before H1: "Loops, repeats after errors and non-submission occur at [X] in the raw trajectories, [Y] in the packed supervision targets and [Z] in the student's rollouts." Every causal word is reserved for the H1 contrast. The chunk view reports first the first supervised action of orphan (later) chunks: repro-script actions at chunk starts would give the student's 0.65 repro-script opener a direct copying route in the targets, weakening "emerge" and strengthening H1's rationale.

1. **Positive adapter control** replaces zero-B as the application test (zero-B stays as the loading-path check): the same M0 adapter with `lora_alpha` 128 (× 8) scored in both stacks; "applied" iff a large change vs base appears in both stacks. 2. **Readings as transfer diff-of-diffs**: D3 = (adapter − base)[vLLM] − (adapter − base)[HF] on the same served ids and span; D1 = (adapter − base)[training form] − (adapter − base)[served form] on HF with the same target ids (identically 0 at step 1 because the two forms coincide there; D1 is informative only at later steps). **Minimum material effect** pre-declared: |Δ| ≥ 0.5 × the adapter's own effect on the same span in the HF training-fit cell, or argmax flips at the first action token / the control token on ≥ 5 of 48 items (sign test); below = "within numeric drift".
3. **vLLM reproducibility**: prefix caching disabled for the diagnostic server; batch composition fixed per scoring; any nonzero repeat difference reported. Repeat scoring is a reproducibility gate, not the noise model; inference = paired per-item differences with a paired bootstrap over the 48 held-out items (plus the base-row cross-stack floor of §G).
