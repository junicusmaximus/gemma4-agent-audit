# Pre-registration: matched-context re-evaluation of M0 (and conditionally M1) — serving form matched to the training form, no training

Author: Boss, 2026-11-06 01:3x KST (2026-11-05 16:3x UTC), before any such run exists (`results/v051_*`, `migration/matched-context-v051/` absent). Frozen at this file's sha256 (session note + 151 copy). Executor: Boss via an executor agent (user decision 2026-11-06). Generation name **v051**.

## Why
The serialization audit (v046) found that at every post-step-1 generation point the trained context ends with the 3-token thought opener (`<|channel>thought` + newline; 23,538 / 23,538 training spans) and keeps an empty thought block before every earlier tool call (25,200 / 25,200), while the v043 serving supplied neither; served M0 emitted `<|tool_call>` directly after `<tool_response|>` (43 / 44). A diagnostic chat template (`analysis/matched-context-boss-v049/chat_template.matched.jinja`, sha256 daf6eacd62920e7652765b818dcad6e1984aeb8692ff876b4bb26b2e964ee92a) restores both: (a) the opener at the generation point after a tool response inside a model turn; (b) the empty block before earlier tool-call turns without a rendered thought; nothing else. No opener at a new model turn (there the opener is supervised in training: 745 / 745 new-turn contexts end at `<|turn>model` + newline). Token-verified on the audited M0 trace: before the first compaction 0 residual spans; over all 48 calls exact equality once the post-compaction header blocks (an artefact of the compacted served prompt) are discounted; M1 trace 79 → 0 opener spans, empty-block 0, the one-token newline residual of earlier non-empty thoughts untouched (kept as served). Harness fields suffice (reasoning_content round-trips only when non-empty; tool messages carry tool_call_id; `enable_thinking` true, thinking budget 4,096); vLLM 0.19.1 accepts `--chat-template <file>`.

## Design intent (one change only)
- Arms: **M0-matched** (`v051_M0mc_s{1,2,3}`) = the sealed M0 adapter (`sft/runs/A1_M0_v035`, sha 7484c311…) served exactly as in v043 (same QAT base, LoRA-on server, same aliasing, sampling T 0.2, seeds 1/2/3, budgets 4 min / 28 calls / 80 turns / concurrency 4, the v043 memory guard 5ad9d40d… and 48 GiB service, the 48-task holdout, canaries) **except** the server is launched with `--chat-template` pointing at the pinned matched template. Conditional **M1-matched** afterwards (same template; the newline residual of earlier non-empty thoughts is a declared, untouched difference).
- Comparator: the sealed v043 M0 (`results/v043_M0_s{1,2,3}`), paired by task × seed — same adapter, same environment, same seeds; the only intended difference is the serving template. A0-capped (v048) is the environment anchor, reported descriptively beside both.
- Launch byte check (stop rule): before the first task, POST `/tokenize` with the messages, tools, `chat_template_kwargs` and `add_generation_prompt` of calls 1, 3 and 7 of the audited trace; the ids must equal the offline matched render; the server log must report the `openai` content format; any mismatch stops the generation (`stopped.json`, no retry). Admission, canary, server-identity and cleanup failures stop likewise.
- Metrics: the pinned producers (`tools/mechanism_metrics_v032.py` 36042f6d…, `tools/analyze_mechanism_v031.py` 821f2294…) on primary40 (ids c7125743…), clean36 and all48; resolution with the unchanged v042 statistics (slot and sign frozen before reading: M0mc − M0). Think-rate is computed from the returned reasoning field (with the opener prefilled, an empty thought parses as reasoning ""); the count of responses with no `<channel|>` (thought text leaking into content) is reported.

## Pre-declared readings (M0-matched vs v043 M0; primary40 three-seed means; every region labelled)
- **MC-i — the serving-form mismatch accounts for most of the behavioural collapse:** loop ≤ 0.30 AND submit ≥ 0.80 AND M5 repeat-after-error ≤ 0.20 (v043 M0: 0.617 / 0.600 / 0.491; A0: 0.00 / 1.00 / 0.04).
- **MC-ii — the serving-form mismatch is behaviourally inert:** |Δ loop| ≤ 0.10 AND |Δ submit| ≤ 0.10 AND |Δ M5-error| ≤ 0.10.
- Otherwise intermediate: reported with the paired 95 % task-bootstrap intervals, no label.
- Resolution is not predicted (expected ≈ 0); pooled resolved(M0-matched) ≥ 4 / 120 is reported as notable and bounded, never as recovery. Think-rate ≈ 0 by construction for M0 (reported, not read). Repro-script first action reported descriptively.
- Interpretation limits: one adapter, one training seed, known holdout; a positive MC-i attributes behaviour to the serving form of THIS pipeline (the kit prefill that training inherited), not to data content; it does not establish that matched serving would make the SFT beneficial; the compaction-summary pathway is unchanged by the template (empty summaries remain possible; `analysis/compaction-audit-boss-v050/` quantifies it) and compaction fires earlier because matched prompts are longer (+3 tokens per post-tool call, +4 per earlier tool call; M0 call 47: 14,349 → 14,528 tokens) — compaction counts per task are reported beside v043's.
